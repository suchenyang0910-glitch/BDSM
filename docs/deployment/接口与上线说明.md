# 同频 Telegram Mini App：接口与上线说明

## 功能边界

Mini App 只提供：

1. 经用户启动 Mini App 后取得最少 Telegram 身份信息；
2. 向自有后端查询会员/订单是否有效；
3. 展示可访问与不可访问的视频目录；
4. 对已授权视频，向后端申请一次性的私密频道链接后跳转。

它不保存用户的 Telegram 手机号，不从前端确认支付，不把固定频道地址写在网页里。

## 当前 Telegram 配置

| 项目 | 当前值 | 用途 |
| --- | --- | --- |
| 公开预览频道 | `https://t.me/InTune_bdsm` | 公开预告、样本内容与品牌通知；可在 Mini App Banner 中直接跳转 |
| 平台 Bot | `@InTune_bdsm_bot` | Mini App 入口、订单通知、权益核验与私密频道邀请发放 |
| 收费频道 | 私密频道（链接不写入代码） | 仅在权益有效后由 Bot/后端按需发放访问入口 |

收费频道的**频道 ID**应只存于服务端环境变量或后台 Telegram 配置中；不要提交到公开仓库。Bot 必须被设为收费频道管理员，且具有创建邀请链接、审核/移除成员所需的最小权限。

## 多 Bot 登录与业务连续性

系统支持多个**已授权、受控**的 Telegram Bot 接入同一个 Mini App。目的仅限于业务连续性和品牌入口管理，不应用于规避 Telegram 的规则、审核或风险控制。

```text
用户从 @InTune_bdsm_bot 或备用 Bot 打开 Mini App
        ↓
Mini App 发送 initData + 可选 botKey（startapp 参数）
        ↓
服务端仅使用 TELEGRAM_BOTS 白名单中的 Token 做 HMAC 验签
        ↓
验签成功后，以 telegram_user_id 查询/创建同一个 users 账户
        ↓
原有订单、内容包和会员权益不变
```

- 用户账户唯一键始终是 `telegram_user_id`，不是 Bot 用户名、Bot key 或某个 Bot Token。
- `botKey` 仅用于优先选择验签候选 Bot；即使该字段被篡改，服务端仍必须通过对应 Token 的 HMAC 验签才能登录成功。
- 备用 Bot 的 Deep Link 使用 `https://t.me/<备用Bot用户名>?startapp=backup`；其中 `backup` 必须与服务端 `TELEGRAM_BOTS` 配置的 key 一致。
- 收费频道邀请由 `TELEGRAM_INVITE_BOT_KEY` 指定的、已拥有频道管理员权限的 Bot 创建；登录 Bot 与邀请 Bot 可以不同。
- Bot Token 永不进入前端、数据库、截图、公开文档或 Git 仓库；新增/停用 Bot 只改部署环境变量并重启服务。

## 本轮校正（Trae 骨架复核后）

- Mini App 现在按服务端返回的 `unlocked` 字段判断单条、内容包和会员权益，避免“已购买单条但页面仍显示未解锁”。
- Banner 外部跳转统一使用后台的 `externalUrl`；公开频道 Banner 指向 `https://t.me/InTune_bdsm`。
- 邀请链接接口只保留 `POST /api/resources/:id/access-link`。旧的 `GET` 路径返回 410，防止浏览器预取或爬虫意外生成入口。
- 演示链接已取消。服务端会调用 Telegram `createChatInviteLink` 创建 1 小时、单次使用的邀请链接；未配置 Bot Token 时返回“暂不能发放入口”，不会假装成功。
- 生产环境必须设置 `SESSION_SECRET`；跨域部署时必须设置明确的 HTTPS `CORS_ORIGIN`，不能使用 `*` 搭配 Cookie。

## 需要的后端接口

| 接口 | 方法 | 用途 | 必须做的事 |
| --- | --- | --- | --- |
| `/api/telegram/session` | POST | 登录并返回会员状态/内容目录 | 校验 `initData` 的 HMAC；以 `telegram_user_id` 查询订单；返回最少资料 |
| `/api/home` | GET | Banner、分类、推荐/精选内容 | Banner 上下线时间过滤；分类 active 状态过滤；按当前会话返回 unlocked |
| `/api/contents` | GET | 两列列表，支持分类/类型/排序/分页 | 按当前会话返回 unlocked |
| `/api/contents/:id` | GET | 内容详情 | 下架内容返回 409；按当前会话返回 unlocked + ownedBy |
| `/api/resources/:id/access-link` | POST | 取得获授权内容的跳转链接（唯一发放入口） | 核验 initData 会话 + 权益/订单；**仅允许 POST**；调用 Telegram `createChatInviteLink` 生成 1 小时单次使用邀请；未配置 Bot Token 返回 503，不返回假链接 |
| `/api/videos/:id/telegram-link` | GET | ⛔ 已废弃（返回 410 Gone） | 防止浏览器预取或爬虫在无用户交互时误发邀请；旧兼容路径不再发放入口 |
| `/api/payment/webhook` | POST | 接收支付成功通知 | 校验支付服务签名；幂等写入订单；更新会员到期日 |
| `/api/admin/entitlements` | POST | 人工补发/撤销权限 | 管理员鉴权、审计日志、双人复核（如有条件） |

## 身份获取与安全要求

Telegram Mini App 可获得用户 ID、名称、用户名、语言和可用头像。前端的 `initDataUnsafe` 可以被伪造，后端只能接收 `initData` 原文并按 Telegram 的 HMAC 校验流程验证后才创建会话。Telegram 官方也明确要求对 `initData` 在机器人服务器上校验。 [Telegram Mini Apps documentation](https://core.telegram.org/bots/webapps)

不要索取用户手机号，除非业务确有必要且用户通过 Telegram 的显式授权流程主动提供。数据库只存服务所需最少信息：Telegram 用户 ID、显示名、订单/权益、创建和到期时间、审计记录。

## 付款状态：唯一可信来源

付款状态只能来自以下其中一种服务端记录：

- 支付服务商签名验证后的异步回调；
- Telegram Stars 的成功支付/订阅事件；
- 经审计的人工确认。

前端按钮、截图、交易哈希输入或用户自行提交的“已付款”状态均不能直接发放权限。若选择 Telegram 内的数字内容收费，Telegram 当前提供 Stars 支付和订阅能力；实际可用性、主体资格、地区规则与税务仍需在上线前核实。 [Telegram Stars payments documentation](https://core.telegram.org/bots/payments-stars)

## 频道跳转的真实风险

私密频道链接不等于 DRM：用户进入频道后，仍可能转发、录屏或泄露内容。因此该方案适合极早期、小规模目录分发与需求验证，不适合长期付费视频资产。

最低限度措施：

- 每位用户只在权限核验成功后获取短期、单次使用的邀请码；
- 不在 Mini App 静态代码、群公告或客服话术中暴露永久链接；
- 定期撤销失效会员的访问；
- 保存授权、投诉与下架记录；
- 真正商业化时改为自有鉴权播放页、短时播放令牌和可追溯水印。

## 零现金上线顺序

1. 在 BotFather 配置 `@InTune_bdsm_bot` 的 Main Mini App HTTPS 地址、菜单按钮和欢迎语。
2. 公开频道 `@InTune_bdsm` 用于预览和引导；将 Bot 设置为收费私密频道管理员，但不要公开收费频道链接。
3. 部署本目录静态前端到已有免费 HTTPS 托管；后端可先只实现身份校验、人工权益表和目录接口。
4. 用 10–20 名受邀用户进行测试，只验证登录、权益识别、目录与跳转。
5. 有合法、可交付的支付方案和退款/支持流程后，才开启收款。

任何实际内容、支付、用户资料处理和地区运营都必须符合目标市场法律、Telegram 规则、支付服务商条款及成年人保护要求。
