# 同频 InTune · 视频点播版页面重构 PRD

> 版本：VOD Phase 1.1
> 产品方向：从“直播社区首页”切换为“视频点播目录 + 付费权益 + Telegram 频道交付”。  
> 核心原则：用户进入后 3 秒知道看什么、10 秒找到内容、1 次动作进入详情或购买。

---

## 1. 当前问题与重构目标

### 当前问题

现有页面把首页、发现、会员、订单、我的五个系统同时铺在首屏 DOM 和产品逻辑中；推荐、已解锁、完整目录、会员商品、订单与个人权益彼此重复。

造成的结果：

- 用户不知道“第一步该看什么”。
- 同一内容在首页、发现、会员多个位置反复出现。
- “会员/内容包/频道”三个概念没有在一个购买路径中说清楚。
- 订单、偏好、通知等低频任务占用了首层导航。

### 重构目标

```text
进入首页
  → 看到一条精选内容或一个主题
  → 打开视频详情
  → 看预览 / 了解权益
  → 选择 Stars 或 USDT 支付
  → 支付成功
  → 获取对应 Telegram 私密频道访问入口
```

首期不把直播、社区动态、钱包积分、主播工具放进用户主导航；这些能力保留后台配置位、数据模型扩展位与功能开关扩展位，但首期不显示、不占用四栏导航，待独立验证后再灰度上线。

## 2. 新的信息架构

### 2.1 底部四栏导航

```text
┌──────────────────────────────────────┐
│ 首页       片库       会员       我的 │
└──────────────────────────────────────┘
```

| 导航 | 用户问题 | 页面职责 | 不应包含 |
| --- | --- | --- | --- |
| 首页 | 今天看什么？ | 单一推荐入口、精选主题、继续观看 | 完整片库、订单列表、个人资料 |
| 片库 | 我想按主题找内容 | 搜索、分类、筛选、内容列表 | 会员介绍、运营横幅堆叠 |
| 会员 | 我该怎么买、买到什么？ | 会员主频道、内容包、权益对比 | 历史订单、后台式说明 |
| 我的 | 我已购买什么、如何管理？ | 已解锁、频道入口、订单、偏好、绑定/设置 | 内容推荐瀑布流 |

顶部仅保留：`同频 Logo`、`搜索`、`通知`。通知不再占底部一级导航。

### 2.2 去除或降级的模块

- `社区`：Phase 1 从用户底部导航移除，后续有稳定 UGC 再通过功能开关上线。
- `直播`、`主播`、`预约`：点播首期全部隐藏，不展示空入口。
- `钱包/积分`：首期不作为用户入口；支付直接在内容详情页或会员页发起。保留后台菜单、数据表与功能开关扩展位，未启用时不展示、也不占用底部导航。
- `订单`：收进“我的”，作为资产管理而非内容发现入口。
- `Banner`：首页支持 0–3 个，按后台排序与上下线时间展示；必须关联明确跳转目标，不使用纯促销广告图或无目标占位卡。

## 3. 页面级结构

### 3.1 首页：只负责“开始看”

```text
┌──────────────────────────────────────┐
│ 同频                 搜索    通知     │
├──────────────────────────────────────┤
│ 真实表达，在理解与边界中被看见          │
│ （单行轻提示，可随内容/活动切换）        │
├──────────────────────────────────────┤
│ Banner 轮播（0–3 个）                   │
│ 内部视频详情 / 分类 / 内容包 / 会员页 /  │
│ 受控外部 HTTPS / 公开 Telegram 链接     │
├──────────────────────────────────────┤
│ 今日精选（仅 1 个大卡）                 │
│ 封面 / 标题 / 时长 / 主题 / 查看详情    │
├──────────────────────────────────────┤
│ 继续浏览（仅当用户有历史记录时出现）     │
│ 最近打开的 1–3 条内容                   │
├──────────────────────────────────────┤
│ 本周主题（2–4 个内容包或分类）           │
│ 主题卡 → 进入片库筛选结果                │
├──────────────────────────────────────┤
│ 最新上架（最多 6 条，两列）              │
│ 查看全部 → 片库                          │
├──────────────────────────────────────┤
│ 首页 / 片库 / 会员 / 我的                │
└──────────────────────────────────────┘
```

首页规则：

- 品牌引导固定为标题栏下的单行轻提示：字号 12–13px、单行省略、总高度不超过 24px；不使用独立大卡或多行 slogan 区。
- 移动端首屏优先级：`顶部栏 → 单行品牌提示 → Banner 或今日精选`；品牌提示不抢占封面与内容标题的可视面积。
- 首屏只有一个主行动：`查看今日精选`。
- Banner 是运营入口，不替代“今日精选”；配置 0 个时整块隐藏，配置多个时首屏只露出 1 张。
- Banner 支持内部跳转：视频详情、分类、内容包、会员页；以及受控外部跳转：HTTPS 页面、公开 Telegram 链接。
- 外部跳转由后台填写标题、副标题、目标 URL、打开方式；禁止私密频道邀请链接、支付收款链接和带用户参数的 URL。
- Banner 后台必须支持：`标题`、`副标题`、`图片`、`跳转类型`、`跳转目标`、`排序`、`启用状态`、`开始/结束时间`。
- 没有观看历史时，不显示“继续浏览”空模块。
- 不在首页展示订单、完整会员商品墙或频道入口。
- 内容卡统一只显示：封面、时长、主题、标题、访问状态；不显示刺激性标签或虚假热度。

Banner 跳转类型固定为：

```text
internal_content     → 内容详情 ID
internal_category    → 片库分类 ID
internal_package     → 内容包 ID
internal_membership  → 会员页
external_url         → 通过 HTTPS/公开 Telegram 链接校验的 URL
```

### 3.2 片库：只负责“找内容”

```text
┌──────────────────────────────────────┐
│ 搜索内容                                │
├──────────────────────────────────────┤
│ 全部 | 分类1 | 分类2 | 分类3 | 精选       │
├──────────────────────────────────────┤
│ 排序：最新（默认） / 最受欢迎             │
├──────────────────────────────────────┤
│ 两列 16:9 视频卡                         │
│ 封面、时长、标题、访问状态                │
└──────────────────────────────────────┘
```

- 首期筛选仅保留：分类、精选、最新/最受欢迎、搜索。
- 点击任意卡片统一进入详情页，不在卡片上直接发起支付。
- `公开预览`、`会员可看`、`内容包可看` 必须用清晰状态，不使用模糊的“已解锁/待解锁”堆叠文案。

### 3.3 视频详情：唯一的转化页

```text
┌──────────────────────────────────────┐
│ 返回                 视频详情            │
├──────────────────────────────────────┤
│ 16:9 封面 / 30–60 秒试看                 │
│ 时长 · 分类 · 上架时间                    │
├──────────────────────────────────────┤
│ 标题                                     │
│ 简介（最多 3 行，可展开）                 │
│ 标签                                     │
├──────────────────────────────────────┤
│ 访问状态卡                               │
│ - 已解锁：前往对应频道                    │
│ - 未解锁：说明可通过会员/内容包访问        │
├──────────────────────────────────────┤
│ 推荐的购买方式（最多 2 个）               │
│ ① 加入会员  ② 解锁所属内容包               │
├──────────────────────────────────────┤
│ 底部固定主按钮：选择支付方式 / 前往频道     │
└──────────────────────────────────────┘
```

购买规则：

- 单条内容不直接交付共享频道权限；只展示其所属的会员或内容包权益。
- `会员主频道`：获得持续更新的会员内容访问。
- `内容包频道`：获得某一主题内容包的访问。
- 用户支付成功后，只进入自己已拥有权益对应的频道；不能把频道链接显示在内容列表或公开响应中。

### 3.4 会员：只负责“理解权益并购买”

```text
┌──────────────────────────────────────┐
│ 会员                                     │
├──────────────────────────────────────┤
│ 当前状态：未开通 / 已开通至 YYYY-MM-DD     │
├──────────────────────────────────────┤
│ 会员主频道                               │
│ 适合：希望持续获得会员更新的用户            │
│ 权益：会员频道访问、持续更新               │
│ [开通会员] / [前往会员频道]                │
├──────────────────────────────────────┤
│ 内容包                                   │
│ 每包：主题、内容数量、价格、已解锁状态      │
│ [查看内容包]                              │
└──────────────────────────────────────┘
```

支付选择弹层：

- Telegram Mini App：默认 `Telegram Stars`，同时提供 `USDT-TRC20`。
- H5：默认 `USDT-TRC20`，并展示 Telegram 登录/打开 Telegram 后可用 Stars 的说明。
- USDT 页面只展示订单金额、TRC-20 收款地址、复制按钮、等待确认状态；不做钱包、积分或复杂充值档位。

### 3.5 我的：只负责“我的资产与设置”

```text
┌──────────────────────────────────────┐
│ 我的                                     │
├──────────────────────────────────────┤
│ 当前账户（用户名） / 本机账户（用户名）       │
│ 账号与安全 / 绑定 Telegram                   │
├──────────────────────────────────────┤
│ 我的已解锁                               │
│ 会员频道 / 已购买内容包 / 可进入频道       │
├──────────────────────────────────────┤
│ 我的订单（待支付 / 已支付 / 已退款）        │
├──────────────────────────────────────┤
│ 内容偏好                                 │
│ 通知设置                                 │
│ 帮助、规则、隐私与反馈                     │
└──────────────────────────────────────┘
```

账号体系原则：

- Telegram Mini App：使用 `initData` 服务端校验后直接登录并绑定 Telegram 账户；“当前账户”直接显示 Telegram 用户名称，页面同时显示“已连接 Telegram”，不出现“访客”字样。
- H5：首次打开自动创建“本机账户”并写入安全、持久的 HttpOnly Cookie；系统需自动生成一个与“同频”品牌相关的随机用户名，用作本机账户显示名；同一设备后续访问自动回到同一账户，不展示登录/注册门槛。
- H5 用户可在“我的 > 账号与安全”绑定 Telegram，用于跨设备恢复已购权益；绑定前后的账户合并必须由用户确认。
- 全站使用 `当前账户`、`本机账户`、`已连接 Telegram` 等中性文案；其中“当前账户 / 本机账户”都必须展示具体用户名，禁止使用“访客模式”。
- 退出本机账户需二次确认，并提示本设备的本地订单和权益入口需要重新登录/绑定后恢复。

## 4. 内容状态和文案统一

| 状态 | 卡片文案 | 详情主按钮 |
| --- | --- | --- |
| 公开预览 | `公开预览` | `查看详情` |
| 可通过会员访问 | `会员内容` | `开通会员` |
| 可通过内容包访问 | `内容包内容` | `查看内容包` |
| 已拥有权益 | `已解锁` | `前往频道` |
| 订单待确认 | `支付确认中` | `查看订单` |

避免：`立即狂欢`、`刺激解锁`、虚假倒计时、虚构在线人数、满屏促销标签。

## 5. 后台如何对应前台

| 后台能力 | 前台落点 | 运营规则 |
| --- | --- | --- |
| 内容分类 | 片库筛选、本周主题 | 分类建议 4–8 个，避免碎片化 |
| 精选开关/排序 | 首页今日精选、首页最新上架 | 今日精选最多 1 条 |
| Banner | 首页运营入口 | 支持 0–3 个；支持内部视频详情/分类/内容包/会员跳转，或受控外部 HTTPS / 公开 Telegram 链接 |
| 内容访问类型 | 卡片状态、详情权益卡 | public/membership/package 三类严格对应 |
| 试看上传 | 详情页播放器 | 30–60 秒、16:9 |
| 完整视频发布 | Telegram 对应私密频道 | 不在 H5/Mini App 直传公开链接 |
| 会员/内容包商品 | 会员页、详情购买选项 | 每条内容至少关联一种权益 |
| 社区/钱包扩展位 | 后台、数据模型、功能开关 | 首期不展示、不占用四栏导航，开启前需单独验收 |

## 6. 前端改造任务清单

### P0：先做减法

1. 底部导航收敛为：首页、片库、会员、我的。
2. 从首页移除订单、我的、完整片库、重复商品区。
3. 首页只保留：品牌引导、Banner（0–3 个条件展示）、今日精选、继续浏览（条件展示）、本周主题、最新上架。
4. 所有内容卡点击进入详情；支付只从详情页或会员页发起。
5. 订单页移入“我的 > 我的订单”；通知移入顶部按钮。

### P1：完成点播体验

1. 详情页增加试看、权益解释、购买方式、支付确认中状态。
2. 会员页区分“会员主频道”和“内容包”，减少术语混淆。
3. 我的页增加已解锁内容、受控频道入口、偏好与通知设置。
4. 统一空状态、加载状态、错误状态与无感账户提示。

### P2：有数据后再做

1. 继续浏览与个性化排序。
2. 内容收藏、观看历史。
3. 社区、钱包、直播、创作者体系保留后台、数据模型与功能开关扩展位，但首期不默认展示、不占用四栏导航。

## 7. 验收标准

- 新用户首页首屏不出现订单、个人资料、频道链接、完整商品墙。
- 首页 Banner 支持 0–3 个，且每个 Banner 都必须配置明确跳转目标、排序与上下线时间。
- 任何内容从列表到购买最多：`列表 → 详情 → 支付方式 → 支付` 四步。
- 用户能在详情页明确知道：该内容属于公开预览、会员还是哪个内容包。
- 已支付用户能在“我的 > 已解锁”看到对应频道入口；未支付用户永远看不到私密链接。
- H5 与 Mini App 使用同一信息架构，只在支付方式优先级上不同。
- 全站不出现“访客模式”文案，只使用：`当前账户`、`本机账户`、`已连接 Telegram`。
- 手机 375px 宽度无横向滚动；所有主操作按钮高度不低于 44px。
