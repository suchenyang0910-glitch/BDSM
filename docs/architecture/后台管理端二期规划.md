# 同频 InTune 后台管理端二期规划

## 1. 目标与边界

管理端的角色不是只做“人工补单”，而是让一名运营人员可以完成内容上架、权益交付、用户服务、风险处置和经营复盘。

首期已完成或在联调的能力：管理员登录、订单列表、订单检索、人工标记支付、审计记录、权益同步。

二期按业务闭环补齐五个域：内容、频道权益、用户与风控、财务、数据。所有涉及真实收款、频道邀请、封禁和退款的操作必须保留操作人、时间、原因和前后状态。

## 3. 功能优先级与验收

| 优先级 | 模块 | 核心功能 | 验收标准 |
| --- | --- | --- | --- |
| P0 | 内容管理 | 发布、编辑、上下架视频；设置封面、16:9 预览、分类、标签、价格、试看、频道交付规则 | 上架内容能在 Mini App 正确展示；下架后不可新购但已购用户权益不受影响 |
| P0 | 首页配置 | Banner、推荐、精选、分类排序、定时生效 | 所有首页模块由后台配置，不在前端写死；配置可预览、可回滚 |
| P0 | 权益与邀请 | 查询权益、补发邀请、撤销邀请、手动授予/撤销权益 | 任何变更写审计；邀请链接不在列表明文长期展示 |
| P0 | 用户管理 | Telegram 用户档案、订单/权益历史、备注、客服限制 | 可按 Telegram ID、用户名、订单号定位用户；客服仅能读取及发起受控处理 |
| P1 | 内容包 | 创建内容包、价格、包含内容、上下架、购买人数 | 内容包变更不误删已购买用户既有权益 |
| P1 | 风控与举报 | 黑名单、购买/访问限制、举报工单、申诉结论 | 封禁和解除必须有原因、期限、操作者与审计记录 |
| P1 | 财务中心 | 收款流水、人工补单复核、退款登记、日对账 | 订单金额、币种、支付凭证、处理人可追溯；财务无权编辑内容 |
| P1 | 数据中心 | GMV、付费人数、付费率、复购、内容销售、渠道转化 | 指标说明清楚，支持按日/周/月、内容、渠道筛选与导出 |
| P2 | 自动化 | 定时上下架、权益到期提醒、异常订单提醒、日报推送 | 可启停、可重试、失败有告警且不重复发放权益 |
| P2 | 工单与消息 | 客服工单、Bot 消息模板、批量通知 | 批量消息有审核、限频、受众预估和发送记录 |

## 4. 页面级需求

### 4.1 工作台

首屏展示今日新增用户、支付订单数、实收金额、待处理订单、待审核内容、异常邀请、未处理举报。每张卡片可进入对应筛选列表。仅展示经营数据，不展示敏感内容封面。

### 4.2 视频内容

列表字段：封面、标题、分类、标签、交付类型、售价、状态、发布时间、购买数、最近编辑人。

编辑页字段：标题、简介、16:9 封面、预览素材或预览 Telegram 链接、分类、标签、单条价格、归属内容包、排序权重、上架时间、私密频道绑定。真正收费频道链接仅保存于服务端密钥配置或频道配置中，前端和普通管理员不可见。

状态：草稿、待审核、已上架、已下架、定时上架、已归档。下架时需选择“停止新购”或“停止访问”；后者仅超级管理员可执行且必须填写理由。

### 4.3 首页配置

支持 Banner、推荐、精选、分类区块四种组件。每个组件都包含生效时间、排序、投放位置、跳转对象、状态和预览。提交后进入待发布状态，由拥有 `homepage:publish` 权限的管理员发布；保留版本和一键回滚。

### 4.4 订单、权益与售后

订单状态：待支付、待核验、已支付、已发权益、已完成、已取消、退款中、已退款、异常。

人工补单必须录入：支付凭证编号、金额、币种、核验人、备注。建议采用“双人复核”：操作员提交，财务或超级管理员确认；低金额紧急补单可由具备特权的角色直接处理，但仍需审计。

权益记录显示来源订单、内容/内容包/会员、开始与到期时间、频道、邀请状态、加入状态。可执行“补发一次性邀请”“重新同步频道成员状态”“撤销未使用邀请”。不得直接复制永久频道链接。

### 4.5 用户、风控与举报

用户页只保留业务必要数据：Telegram 用户 ID、用户名（若提供）、首次访问、最近访问、订单统计、权益状态、风险标记、客服备注。不得要求或保存与业务无关的身份信息。

限制动作分为：禁止购买、禁止访问、禁止接收邀请、限制期限、解除限制。所有处罚须有依据编号；举报处理保留原始举报、结论、处理人、申诉结果。

### 4.6 财务与数据

财务按“订单金额、实收金额、退款、手续费、净收”分层；USDT 订单额外记录链、币种、交易哈希、到账地址标签和确认数（如适用），交易哈希应做唯一性校验。

数据报表首期使用“已支付订单”口径计算 GMV，不把人工创建但未支付的订单计入。每个图表提供口径说明和时区说明（统一使用 Asia/Bangkok 或明确的业务时区）。

## 5. 角色与权限

| 角色 | 可以做 | 不能做 |
| --- | --- | --- |
| 超级管理员 | 全部配置、频道绑定、发布、资金确认、权限管理 | 不应使用共享账号 |
| 运营 | 内容草稿、首页提案、数据查看、用户备注 | 不能补单确认、退款、查看 Bot 密钥 |
| 财务 | 收款核验、补单复核、退款登记、财务报表 | 不能编辑内容或频道配置 |
| 客服 | 查用户、查订单、登记工单、申请补发邀请 | 不能直接标记支付、封禁、退款 |
| 风控审核 | 举报、限制建议、解除建议、审计查看 | 不能操作资金与频道密钥 |
| 审计只读 | 查看审计、订单与报表 | 不能写入任何业务数据 |

权限采用细粒度权限码，例如 `content:edit`、`homepage:publish`、`order:mark_paid`、`entitlement:resend_invite`、`finance:refund`、`user:restrict`。高风险权限默认最小化分配。

## 6. 必须遵守的安全规则

1. 不在后台页面、前端接口或导出文件中返回 Telegram Bot Token、私密频道永久链接、支付密钥。
2. 频道邀请由后端即时生成，设置单次使用、短有效期，并记录邀请创建、使用、撤销状态。
3. 管理员登录采用密码哈希、短会话、退出失效；生产环境禁止演示登录接口和默认密码。
4. 支付成功、退款、权益授予/撤销、用户限制、频道配置改动全部在同一事务或可靠事件链中记录审计。
5. 导出数据按角色限制字段，默认不导出敏感备注、支付凭证原件和完整 Telegram 资料。
6. 内容审核、举报与处罚按适用法律、平台规则和成年人安全边界执行；不把后台当作规避平台规则的工具。

## 7. 二期实施顺序

### Sprint 1：内容可运营（约 5–7 个工作日）

- 内容、分类、Banner/推荐/精选的后台配置与前端读取。
- 视频、内容包状态机和首页配置版本。
- 内容上架、下架、定时发布审计。

### Sprint 2：权益可交付（约 4–6 个工作日）

- 权益列表、补发邀请、邀请状态同步、到期任务。
- 用户详情与订单/权益时间线。
- 订单人工补单双人复核。

### Sprint 3：经营可复盘（约 5–7 个工作日）

- 财务流水、对账、退款登记。
- 经营总览、内容销售和转化漏斗。
- 举报/限制/审计查询。

### 上线门槛

- P0 全部完成并通过权限、审计、重复发放、下架内容、过期权益五类回归测试。
- 真实私密频道环境下完成一次从支付核验到成功入群的验收。
- 演示登录、默认管理员密码、占位频道 ID 和测试 Bot Token 全部从生产部署中移除。
