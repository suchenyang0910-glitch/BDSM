# 同频 InTune 产品与后台技术 PRD

## 1. 用户端信息架构

```text
Mini App
├── 首页 / Banner / 分类 / 视频列表（两列）
├── 分类 / 内容包
├── 视频详情
├── 订单支付状态
└── 我的
    ├── 我的已解锁内容
    ├── 我的内容包
    ├── 会员状态
    ├── 订单记录
    ├── 社区公约
    └── 客服
```

## 2. Mini App 页面要求

### 2.1 首页运营位、分类与视频列表

- Banner：支持多条横滑推荐位；后台配置标题、文案、封面、排序、展示周期和跳转目标（内容、内容包、分类或合规外链）。
- 分类：后台创建、排序、启用/停用；前端横向标签栏展示。支持“全部、精选、推荐”等系统分类与运营自定义分类。
- 布局：移动端两列网格；间距 10–12px；视频封面固定 16:9。
- 卡片字段：封面、标题、标签、时长、价格、解锁状态、内容类型。
- 内容类型：`public`、`single`、`package`、`membership`。
- 卡片状态：加载骨架、正常、已解锁、待支付、下架、无内容、请求失败。
- 筛选：全部、预览、单条、内容包、会员；可按最新/热门排序。
- 不在列表中展示永久频道链接或实际频道 ID。

### 2.2 视频详情

- 字段：封面、标题、简介、内容包归属、时长、发布日期、权益类型、价格、预览说明。
- 未解锁：显示购买入口和“付款后自动开通”的说明。
- 已解锁：显示“前往观看”；点击向服务端请求访问入口。
- 下架：已购用户提示“内容暂不可用，请联系客服”，不再给出旧链接。

### 2.3 我的

- 显示 Telegram 头像、昵称、会员状态与到期时间。
- Tab：已解锁内容 / 内容包 / 订单记录。
- 订单行：订单号、商品、金额、币种、状态、创建时间、有效期。
- 支持入口：支付异常、邀请链接失效、退款申请、内容举报。

## 3. 商品与权益模型

| 商品类型 | 用户购买什么 | 权益如何交付 | 推荐程度 |
| --- | --- | --- | --- |
| 单条内容 | 一条独立内容 | 独立私密频道或后续自有播放器 | 可做，但频道运营成本高 |
| 内容包 | 一个主题下多条内容 | 进入一个内容包私密频道 | 首期推荐 |
| 月会员 | 持续更新内容 | 进入会员私密频道，按到期撤销 | 首期推荐 |

商品和权益必须分开：商品是价格与订单；权益是“哪个用户在什么时间范围可访问哪个资源”。

## 5. 管理后台模块需求

### 5.1 内容管理

- 创建内容时填写：标题、封面、描述、时长、分类、标签、内容类型、商品、资源频道、状态、授权附件/编号、审核结论。
- 状态：草稿、待审核、已上架、已下架、已归档。
- 下架后立即停止新购买与新链接发放；保留订单和历史审计。
- 内容包可关联多条内容，配置包价格、封面、描述、目标频道。
- 内容支持运营标签：推荐、精选、新上架；后台可设置排序权重及推荐展示周期。

### 5.1.1 首页运营位管理

- Banner CRUD：封面、标题、短文案、按钮文案、跳转类型、跳转目标、排序、上线时间、下线时间、启用状态。
- 分类 CRUD：名称、图标/封面、排序、启用状态；停用分类不在前端导航展示。
- 推荐/精选：从已上架内容中选择，配置首页排序与有效期；前端通过 Home API 拉取，禁止在前端固定推荐内容。

### 5.2 用户管理

- 用户主键为 Telegram User ID。
- 可查：注册时间、昵称、订单数、累计支付、权益、到期日、最近访问、风险状态。
- 动作：人工授予权益、撤销权益、冻结、解冻、备注；每项动作必须填写原因。

### 5.3 订单管理

- 状态：`pending`、`processing`、`paid`、`failed`、`refunded`、`cancelled`、`expired`。
- 支持查看回调流水、支付渠道订单号、商品、用户、金额、币种、权益生效结果。
- 人工补单必须二次确认并保留操作日志；退款后自动进入撤销权益任务。

### 5.4 财务管理

- 看板指标：订单金额、实收金额、退款金额、净收入、支付用户数、付费转化、客单价、复购率、有效会员数。
- 维度：日/周/月、商品、内容包、支付渠道、推广来源。
- 支持 CSV 导出；金额不得由前端计算，须由服务端订单账本汇总。

### 5.5 数据管理

- 事件：Mini App 打开、列表曝光、内容点击、详情浏览、下单、支付成功、权益发放、频道链接领取、频道加入失败、退款申请。
- 漏斗：打开 → 查看详情 → 创建订单 → 支付成功 → 权益发放 → 内容入口领取。
- 用户数据按 Telegram User ID 去重；不采集不必要个人信息。

## 6. 角色权限（RBAC）

| 角色 | 权限 |
| --- | --- |
| 超级管理员 | 全部权限、管理员管理、财务导出、Telegram 配置 |
| 运营 | 内容、内容包、用户备注、数据查看；不能改财务和管理员 |
| 客服 | 查询用户/订单、提交退款/异常工单；不能直接改价格或财务 |
| 财务 | 对账、退款审核、财务导出；不能发布内容 |
| 审核员 | 查看授权、审核和上下架建议；不能操作订单 |

## 7. 第一版不纳入范围

- 钱包余额、虚拟币、积分、充值、转账。
- 主播开播、直播间、连麦、礼物、PK。
- 复杂会员等级、任务体系、公会、推广分佣。
- 私信、附近的人、用户自由上传内容。
