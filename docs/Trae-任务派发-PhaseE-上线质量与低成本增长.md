# Samewave · Phase E 开发任务书：上线质量、低成本增长与运营闭环

> 当前基线（已交付）：私有对象存储、分片断点上传、FFmpeg 转码、60 秒试看与 1080p / 720p / 480p HLS 产物、同域 Cookie 受控播放出口、同源固定版本 HLS.js、封面受控路由、观看进度、会员到期/宽限期处理均已存在。

## 一、绝不回退的产品与安全边界

1. **完整视频唯一来源**：后台仅上传完整源视频与封面；Worker 自动生成 60 秒试看 HLS 和完整 HLS，不要求运营另传试看视频。
2. **付费正片永不公开**：浏览器、Mini App、日志、审计和前端状态中不得出现完整对象 Key、Bucket 地址或永久媒体 URL。
3. **播放入口唯一**：仅允许 `/playback/:contentId/:variant/*` 受控出口；验证 Cookie、会话、内容状态、权益、到期与撤权。不得新增绕过 API 的 CDN/对象存储播放链接。
4. **试看体验**：进入详情即准备 60 秒试看流，但不得自动播放；用户点击原生播放键后才写入观看进度。试看结束必须在播放器内显示购买入口。
5. **续费体验**：会员有效时显示到期日与“立即续费”；已过期或宽限期显示“续费恢复权益”。续费必须从现有到期日顺延，不能覆盖为当前时间。
6. **流量入口**：公开频道、Bot 深链、官网、社媒等统一视为“免费流量入口”；发布会员内容时必须生成封面推广帖和内容详情深链，失败可重试且不重复发布。
7. **隐私与合规**：只保留聚合漏斗与脱敏标识；不得在运营页显示完整 IP、完整 UA、Telegram ID、钱包地址、频道 ID、邀请链接、密钥或媒体对象路径。

## 二、E0：PC Web 视频平台布局重构（P0）

> 参考的是主流视频站的**信息架构与浏览效率**，不是复制 YouTube 的品牌、图标、文案、颜色、动效或任何受版权保护的素材。Samewave 保持自己的深色紫灰品牌系统和“同频”内容定位。

### 强制布局规范

| 区域 | 必须实现 | 禁止事项 |
|---|---|---|
| 顶部栏 | 高度 64px；左侧仅“同频”品牌，中间为主搜索框，右侧为通知与“我的”入口 | 不得以域名 Samewave 替换产品主名称；不得把搜索、通知拆为第二行；不得在首页显示返回按钮 |
| 左侧栏 | 240px 固定侧栏：首页、片库、会员、我的；底部放规则/反馈，当前项以品牌色细竖条标记 | 不得重复底部四栏导航；不得把运营后台入口混入用户侧导航 |
| 主内容区 | `minmax(0, 1fr)`，片库桌面任何宽度始终 4 列；超宽屏仅放大卡片与间距，卡片封面为 16:9 | 不得改为第 5 列；不得固定窄卡片导致大屏一行只出现 2–3 条；不得出现横向页面溢出 |
| 右侧栏 | 首页与“我的”显示 300px 的继续观看、会员状态、待支付订单；小于 1280px 自动收起并移至主内容底部 | 不得遮挡内容卡片或产生右侧露出半张 Banner |
| 卡片 | 封面优先，标题最多两行；时长、权益标签叠在封面；价格与 CTA 仅在 hover/focus 或详情区显示 | 不得用大段介绍挤压封面；不得显示对象存储 URL/频道 ID/内部状态 |

### 页面级规范

1. **首页**：顶部栏 → 可选单张 Banner（最多一张且不露出下一张）→ “继续观看”（有记录才显示）→ 今日精选（4 列）→ 最新上架（4 列）。主题仅作为一行可横向滚动的筛选 chips，不得占用大面积首屏。
2. **片库**：搜索与筛选固定在内容区顶部；结果以 4 列封面瀑布流展示。筛选条件为全局、可见、可清除，空结果需有“清空筛选”按钮。
3. **视频详情 / 播放页**：采用 `minmax(0, 1fr) + 360px` 双栏。左侧为 16:9 播放器、标题、标签、描述；右侧为“接着看/相关推荐”。小于 1280px 时右栏下移，不能压缩播放器。试看结束 CTA 必须直接覆盖在播放器中，主操作仅一个：`开通会员`、`购买此片` 或 `继续观看`。
4. **会员页**：先展示当前状态与到期日，再展示一个明确的“立即续费/恢复权益”按钮；其下才是权益内容。有效、到期、宽限期都必须能一次点击进入正确收银台。
5. **我的页**：账户、继续观看、订单、已解锁内容、频道备用入口按此顺序排列；不出现“本机账户”，首次自动登录生成并永久保留中性随机昵称。

### 交互与可访问性

- 所有卡片点击区域应完整覆盖封面与标题，键盘可聚焦，`Enter` 可打开详情。
- 播放按钮、试看结束 CTA、购买/续费按钮要有 loading、成功、失败、可重试四种状态，不能只弹无上下文的 toast。
- 图片加载使用 16:9 skeleton；加载失败显示品牌占位图与“重试加载”，不出现黑块或高度跳动。
- 断点：`>=1024` 固定四列；`768–1023` 三列并收起右栏；`<768` 切回移动端 IA，不能沿用 PC 固定侧栏。

### E0 验收清单

1. 1440px、1280px、1024px、768px、390px 各一张首页/片库/详情截图；任意宽度无页面级横向溢出。
2. 桌面首页 Banner 只显示一个完整 Banner，右侧不允许露出下一张卡片。
3. 1280px 桌面片库为四列，封面均为 16:9；详情播放器不小于主列宽度的 16:9 比例。
4. 完成首页 → 片库 → 详情 → 点击试看 → 试看结束 CTA → 会员/续费入口 → 我的订单的浏览器实测录像或截图链路。
5. 不得新增外部视频平台资源、第三方播放器 CDN、品牌抄写或用户隐私字段。

## 三、E1：真实播放验收与播放器质量（P0）

### 任务

- 为 H5 和 Desktop Web 增加播放器加载、首帧、缓冲、错误、清晰度切换、试看完成与购买入口点击的白名单埋点。
- 加入 `saveData`、弱网、后台标签页和暂停超过 30 秒的预取停止条件；默认只预读后续 1–2 个切片。
- 默认策略：弱网 480p、移动网络 720p、Wi‑Fi 自适应；用户选择清晰度后优先遵从用户选择。
- 对播放失败统一显示“重试试看”，禁止暴露内部错误、对象路径或签名地址。
- HLS.js 已改为同源固定版本静态资源；必须保留这一路径的自动化回归，不得重新依赖第三方 CDN，避免 Chrome/Edge 因地区网络不可用而无法播放 HLS。

### 验收清单

| 场景 | 必须结果 |
|---|---|
| 未购买账户 | 可手动播放 60 秒试看；正片会话/清单/切片均被拒绝 |
| 有效会员 | 480p 起播，可切换 720p/1080p；刷新后可续看 |
| 单条购买 | 只能看该条内容，不能横向访问同频道或同内容包其他视频 |
| 退款、到期、下架 | 下一次 manifest/segment 请求立即被拒绝，撤权有审计 |
| 复制 URL | 缺 Cookie、过期 Cookie、跨内容 Cookie 必须 401/403 |
| 移动端与桌面端 | 手机两列、桌面片库四列；封面 16:9 `object-fit: cover`，无黑块、无横向溢出 |

## 四、E2：商品、支付与续费转化（P0）

- 内容页仅显示适用商品：月度会员、内容包或单条购买；运营端未配置商品必须可见地报错，用户端不得出现“当前内容没有可用商品”。
- H5 和 Mini App 均支持 USDT-TRC20；Telegram Stars 仅在 Telegram 环境和可用账户条件下展示。Stars 失败/取消后保留订单并无损切换 USDT。
- USDT 收银台只显示：订单号、金额、收款地址、二维码、复制按钮、自动轮询状态；链上监听确认才可发放权益。
- 成功后必须同步订单、权益、播放资格、频道备用入口、页面成功态与脱敏运营通知；通知支持复制截断订单号，但不显示收款地址或真实用户资料。
- 试看到期遮罩的购买按钮应直接打开对应收银台，不能先跳转空白页或要求重新登录。

## 五、E3：免费流量入口与归因（P1）

- 将公开 Telegram 频道、Bot `/start content_<id>`、官网、Facebook/X/社媒、合作渠道统一建模为免费流量入口。
- **公开链接域名不可从请求 Host 推导。** 后台请求可来自 `admin.*`、API 可来自 `api.*`；生成的 H5 深链必须只使用服务端 `PUBLIC_WEB_ORIGIN`，Mini App 深链必须只使用独立的 `TELEGRAM_MINI_APP_ORIGIN`（即 BotFather 配置的 origin）。不得生成 `/h5/` 或 `/mini-app/` 这样的假定路径，也不得生成 `admin.*` 域名链接。
- 流量入口 resolve 的回归必须注入伪造后台 Host，并断言两类公开链接仍为 HTTPS、仍落在上述两个受控 origin。入口码只作匿名归因，不得承载用户、权益、订单、媒体对象或支付信息。
- 发布会员内容时，对全部已启用公开入口默认生成：封面、标题、简述、Telegram 标签与带内容参数的深链；运营不需要逐个勾选频道。
- 频道发布幂等键：`contentId + entryId + publishVersion`；重复提交只能得到同一任务。失败状态可重试，成功不可重复发帖。
- 后台漏斗至少按入口、内容、日期展示：详情打开、试看开始、试看完成、收银台打开、支付成功、GMV、转化率与有效成本。入口码仅用于归因，绝不授予权益。

## 六、E4：成本、可靠性与运维（P1）

- 转码 Worker 默认单并发；指数退避、最大重试、租约回收、失败类别与人工重试入口齐全。禁止无限重跑。
- CDN 预热仅允许刚发布视频的试看清单与首段、以及热门内容；必须有每日对象数/带宽/费用预算，超限自动停止。
- 不实现 BT/P2P。它会带来版权、隐私、作弊、审核与客户端兼容性风险，短期成本收益不足以抵消风险。
- 告警覆盖：Worker 停止、转码失败率、对象存储错误、播放 401/403 异常、首帧超时、支付确认延迟、收款地址完整性异常。告警仅含聚合计数和脱敏指纹。
- 每日 PostgreSQL 备份、对象版本与生命周期策略、下架媒体恢复窗口必须有演练记录。

## 七、E5：代码质量与上线门禁（P0）

- 每个 API 写操作必须有：鉴权、角色权限、Zod 输入校验、参数化数据库查询、审计与幂等策略。
- 任何 BigInt 出口必须显式字符串化；前端/后台不得因 BigInt 序列化失败白屏。
- 图片和封面一律由受控 `/api/contents/:id/cover` 映射，前端不存储稳定对象 URL。
- SEO 页面不输出露骨标题、付费媒体对象信息或受控播放路径；私密业务页面保持 `noindex`。
- 每批上线流程：本地类型检查与测试 → staging 迁移及真实对象存储验收 → H5/桌面像素验收 → 灰度 → 生产。不得以生产库替代测试库。
- **测试库必须互斥。** 所有自动化进程在使用 `DATABASE_URL_TEST` 前必须取得跨进程锁（或为每次运行创建独立测试库）；拿不到锁应明确等待或失败，严禁两个测试进程同时 truncate 同一测试库而制造假红或假绿。
